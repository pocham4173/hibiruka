# 写真と記録の一括保存（2026-10-01）

## 修正した動作

新規作成・編集とも、記録と最大4枚の写真を同じFirestoreバッチで確定する。写真だけ失敗して記録が残る状態を作らない。初回作成の事前書き込みは廃止。

同じ入力画面で再試行した場合は下書きIDを維持する。成功応答が失われていても、サーバーで既存記録を確認して更新し、作成日とLINE通知予約を上書きしない。画面を閉じる前にまだ保存できていなかった入力内容を、後から自動復元する機能は含まない。

写真の縮小処理中は保存を開始せず「写真を準備中」と表示する。保存中は入力欄を一時停止し、写真とサムネイルの組み合わせが途中で変わらないようにする。

## 権限・公開順序

personalPhotosの親記録確認にgetAfterを使用し、一括作成される親のownerUidを検証する。他人の記録・写真、親のない写真への書き込みは拒否する。従来コレクションのルールは変更しない。

1. 現在の本番ルールに変更を組み込み、エミュレータで権限を検査。
2. ルール公開。一時アカウントで本番の記録＋写真4枚を同時保存し、不正な写真を含む保存は全体が拒否されることを検査。一時データは削除。
3. 検証成功後、フロントエンドを公開。

## 検証

- バッチ失敗時に新規記録・写真がどちらも残らない。
- 編集失敗時に前の記録と写真が維持される。
- 成功応答の欠落後に再保存しても重複しない。作成日時と通知予約を維持する。
- 写真準備中に保存しても写真抜きの記録を作らない。
- 個人用・従来用の最大4枚同時保存と他人からのアクセス拒否。

実機でアプリを強制終了する試験は未実施。LINE認証・通知容量の改善はこの変更に含めない。
