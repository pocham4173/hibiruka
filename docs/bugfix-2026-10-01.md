# 保存・予約処理の修正

- 写真の取得失敗・欠落時は編集を中止。サムネイルを原本として再保存しない。
- 編集では記録・写真・サムネイルを同じバッチで更新。
- 新規作成は同じ下書きの ID を通信失敗後も使う。最初に写真なしの記録を確保し、写真とサムネイルを一括確定する。既存ルール互換のため新規全体はまだ単一トランザクションではない。途中失敗して画面を閉じた場合、写真なしの記録が残り得る。
- 不正形式の通知は失敗状態にし、待ち行列から外す。他の記録の処理を続行する。
- 個人用と従来用のキューは予約時刻順。予定開始から15分以内は遅延通知を許容し、それ以上古い予定は送らない。毎分2件の上限は変更しないため大規模利用の容量問題は未解決。
- Worker は接続確認のみで公開、実際の定期実行を2回確認後に既存予約の送信を再開、さらに2回の定期実行を確認する。旧 GitHub 送信は停止したまま。
