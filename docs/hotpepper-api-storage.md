## 規約で確かめたこと（公式）

- ご利用案内（webservice.recruit.co.jp/doc/hotpepper/guideline.html）
  - APIを使う画面にクレジット「Powered by ホットペッパーグルメ Webサービス」を出す
  - 画像を使うときは【画像提供：ホットペッパー グルメ】と明記する
  - 「アフィリエイトにより収入を得ることは問題ありません」
- 利用規約（webservice.recruit.co.jp/regulation.html）
  - キャッシュは、個別の定めがなければ「24時間以内」に更新する
  - 取得した情報を「第三者のデーターベースに複製保存し、…」とする条文がある（禁止の範囲の全文は、こちらで読み切れていない）
- 「24時間ごとに取り直せば、複製保存の問題もすべてなくなる」とは言えない。キャッシュの更新と、複製保存の禁止は別の決まり。

## どこに・何を・どれだけ残しているか

| 場所 | 残している項目 | APIから来たもの | 本人が入れたもの | 期間 | 表示する所 |
|---|---|---|---|---|---|
| Cloudflare Worker の検索キャッシュ | 検索APIの返事 | 全部 | — | 1時間（`cacheTtl: 3600`） | 検索結果 |
| 行きたいリスト（`personalEvents`、`kind: "wish"`） | 店名・ジャンル・住所（メモ欄）・写真のURL・座標・お店のページ・お店のID | 全部（`infoSource: "hp"`、写真は `imageSource: "hp"`） | なし（「行きたい」と選んだこと自体） | 本人が消すまで | アプリの行きたいリスト、LINEの「行きたいリスト」カード |
| お店から作った予定 | 「どこで？」（店名）・メモ（住所）・座標・お店のページ（`shop`） | 最初の値はAPI | 本人が直せる（直したら座標・お店のページは外す） | 本人が消すまで | 予定・カレンダー・地図・LINEのお知らせ本文 |
| おでかけコース（その端末の localStorage） | 店名・座標など | API | — | 本人が外すまで（その端末だけ） | コースの画面 |
| 送信台帳の本文の控え（`sendLedger.linePayload`） | 予定の題名・場所・メモを含むLINEの本文 | 予定経由で一部 | 予定の内容 | LINEの送信が終わるまで（終わったら消す） | 表示しない（サーバーだけ） |

- 写真は画像そのものではなく、ホットペッパーの画像のURLを残している（表示のたびにホットペッパーから読み込む）。
- 2026-10-10 から、行きたいリストに `infoSource`・`imageSource` を残す。以前の版で保存した写真のURLも、ホットペッパーの検索結果からしか保存できない作りだった（コードで確認）ので、同じく「画像提供」を出す。
