# 旧共有領域の非公開化：切り替え準備

この文書と変更は準備段階。本番の非公開化が完了したことを示さない。
個人の番号、UID、記録内容や本番の集計結果はこの文書に記載しない。

## 完成条件

- 既存の予定・写真・買い物・ペット記録を失わず、確認した本人が開ける。
- 別のアカウントはアプリ、直接のデータ取得、LINEから旧記録を読めない・変更できない。
- LINE送信先への登録だけでは記録の閲覧権限を与えない。送信は本人が選んだ予定・相手に限定する。

## 実装済みの準備（未公開）

`line-worker/webhook.mjs` は、旧領域へのLINE操作のたびに現在の owners/members を再確認する。
管理者だけが設定する `config/legacyPrivacy` がある場合は、その本人限定の指定を優先し、
古い owners/members が残っていてもそれを根拠にアクセスさせない。
以前の双方向LINE連携が残っていても、この両方から権限を外したアカウントは記録を読めない。
権限確認の通信失敗は記録へのアクセスを許可しない。連携番号による再接続にも同じ判定を使う。
これは現行の旧所有者判定との整合を取る変更であり、旧共有の仕組み全体の廃止ではない。
権限変更と同時進行中のリクエストを強制中断するものでもない。

`scripts/legacy-owner-identity.cjs` は問い合わせ番号と既存の所有者候補を照合する純粋関数。
ネット接続・書き込み・ログ出力はない。問い合わせ番号は本人認証用の秘密ではない。
管理者が別途得た本人の確認と作業許可のもとでのみ使う。これを公開の所有権取得APIにしてはいけない。
推測による割り当て、全利用者への複製、LINEの送信先からの所有者推定は行わない。

`scripts/legacy-private-rules.cjs` は本番ルールの isOwner と旧 members / owners の許可を狭める。
未知の重複許可や既にある個人化ルールを検出したら止まる。
読み取り専用の事前検査で本番ルールを一時ファイルにのみ保持し、架空のアカウントで5項目を検証済み。
本番ルールの公開、利用者データへのアクセス、ルール適用はしていない。

画面は `legacyPrivacy` の本人一致・version 1・activated true をすべて確認したときだけ、
非公開の説明に切り替えて旧PIN変更の案内を隠す。保存先とIDは変えない。
activated は本番ルールとLINE処理の適用・拒否確認が完了するまで設定してはいけない。

## 本番切り替え前の必須作業

1. いつもの記録が見える端末の問い合わせ番号を受け取り、候補に一意に一致するか内部で確認する。
   不一致・複数一致なら停止。UIDや番号を公開ログやリポジトリへ出さない。
2. 最新の本番ルールを非公開の作業領域で取得し、旧領域を許可するすべての条件を確認する。
   追加した拒否条件だけでは別の許可条件を打ち消せない。テスト用旧ルールを本番の代用にしない。
3. 記録の保存先とIDを維持し、確認した本人だけに旧領域を許可する最小変更を作る。
   owners/members の書き換えによる自己昇格、旧PINからの再参加も閉じる。
   再参加の停止をせずに owners から外すだけでは完成にしない。
4. LINE Worker の権限再確認と合わせ、既存のLINE連携・送信予約・台帳を扱う手順を検証する。
   予約の複製や再送を起こさない。送信先リストと閲覧権限は別物として扱う。
   既存予約を勝手に削除したり、一括で新たな相手に送信してはいけない。
5. 公開前に、実際のルールを元に隔離エミュレーターで本人の許可・別人の拒否・PIN再参加拒否・
   owners/members 自己昇格拒否を検査する。LINE経路でも一覧・変更・削除・再接続を検査する。
   バックアップは同一プロジェクト内の管理者限定領域など、権限を狭めた場所に作り復元を検証する。
   旧ルールへ戻して共有範囲を再び広げる復旧は行わない。
6. 切り替えでは処理中リクエストと新規書き込みの競合を止め、再確認済みスナップショットだけを使う。
   確認した端末のアクセスを残してから他の権限を閉じる。
   本番適用後の本人の読み書き、他人の拒否、記録件数・ID・内容の維持を確認する。

## 今回変更しないもの

本番ルール、利用者データ、アカウント登録、LINE送信先、送信予約、公開サイトは変更しない。
画面の「共有」表示だけを消して安全になったように見せない。
本人の端末確認前に候補からどれかを選んで本番権限を変えない。
