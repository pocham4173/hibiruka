## 2. 最初に改善した導線：飲食店を選ぶ → 予定にする → そのお店のページ

選んだ理由：
- **目的と行き先が一致する**：お店を選んで予定にした人が開くのは、そのお店のページ（県や全国のページではない）。
- **予定を決めるときに自然に必要**：予定を開くとき（日時を決めた後・出かける前）に、席・メニュー・ネット予約を確かめたくなる。
- **余計な検索が減る**：以前は予定にするとお店のページへのつながりが消え、もう一度探す必要があった。
- **維持費・更新作業がない**：すでに取っているお店検索の結果を残すだけ。追加のAPI・費用・更新作業なし。
- **成果対象**：ホットペッパーの提携が承認されれば、`vcOn` を `true` にするだけで成果対象のリンクに切り替わる。**承認状態は未確認**。承認までは通常リンク（PRなし・報酬なし）として、利用者の役に立つかと表示・押下の数だけを先に見る。

実装：
- お店検索の結果（または行きたいリストのお店）から予定にすると、そのお店のページを予定に残す。「どこで？」を別の名前に直したら外す。
- 先の予定の詳細だけに「🍽 ホットペッパーでこのお店を見る」を出す。思い出・過ぎた予定には出さない。
- 空席・予約の可否は取得していないので「予約する」とは書かない。「外部サイトが開きます。空席・ネット予約ができるか・最新の情報は、開いた先で確かめてください。」と添える。
- 承認後の広告リンクには「PR」と `rel="sponsored"` を付ける。報酬で表示順を変える仕組みはない（ボタンは1つだけ）。
- 予約しなくても、記録・予定・通知はこれまでどおり使える。
- ついでの修正：クーポンがないお店の結果に「🎟 クーポン・予約」と出ていたのを、クーポンがあるときの「🎟 クーポンを見る」だけにした。

## 4. 49点の原因の整理

**① 実装で改善できること**（このPRで一部対応）
- リンクの正確さ：行き先と一致しない県・全国のリンクが多い → 予定のお店に直結する導線を追加した。
- 予約導線：予定にするとお店へのつながりが消えていた → 残すようにした。
- 表示位置：予定の詳細（行く前に見る場所）に置いた。探す画面のボタンは増やしていない。
- 説明：外部サイトであること、空席・予約は先で確かめることを明記。「予約」と書けない所から「予約」を外した。
- 計測：表示・押下を数えられるようにした。
- 残り：5・12 の見直し、ほかの導線の一致度の改善（今回は1つに絞ったため未着手）。

**② 実際の利用がないと分からないこと**
- 押される割合、押した後に予約・購入まで進む割合、繰り返し使われるか、便利だと感じられるか。いまは**すべて未確認**。

**③ 運営側で必要なこと**
- ホットペッパー（バリューコマース）の提携承認と `vcOn` の切り替え。
- 成果の確認（管理画面）、入金条件の確認（最低支払額など。公式の案内で確認）。
- 継続的な利用者獲得（紹介用QRコードなど）。導線の改善とは分けて考える。

## 6. 少人数での検証（最初は導線1つだけ）

対象：家族・知人など数人。期間は「数週間・少なくとも表示が数十回たまるまで」。短い期間の数字で成功・失敗を決めない。

見ること：
1. お店を探して予定にしたあと、予定から目的のお店に迷わず行けたか（本人に聞く）。
2. 「このお店を見る」が必要な場面で見つかったか（聞く＋①）。
3. 広告が邪魔で記録や予定作りをやめていないか（聞く。予定・思い出の件数が減っていないか）。
4. 押す理由があったか（聞く＋②÷①）。
5. 成果が少ないときの切り分け：
   - ①が少ない → お店から予定を作る人が少ない（**表示不足**：利用者獲得・探す機能の使われ方の問題）
   - ①はあるが②÷①が低い → ボタンの位置・文言・必要性（**クリック不足**）
   - ②はあるが③が少ない → 予約先の使いやすさ・お店の予約対応状況（**成約不足**）。承認前は③は未取得なので判断しない

## 7. 運営の手順

1. ホットペッパー（バリューコマース）の提携が承認されたら、`index/index/index.html` の `CONFIG.affiliate` の `vcOn: false` を `true` に変える（依頼してもらえれば変更します）。
2. 公開後、探す画面と予定の詳細の各リンクを1回ずつ開き、目的のページが出るか確かめる（リンク切れの確認）。
3. 月に1回、Actions の「ヒビルカの状態確認（読むだけ）」で①②を見て、管理画面の③④と一緒に 3章の表へ書く。
