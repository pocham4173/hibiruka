# 通知の送信台帳（2026-10-09）

予定のお知らせ（LINE・アプリ通知）の「確保した通数・処理中の印・手段ごとの結果」を、利用者が書けない場所に移した。

## 置き場所

| 置き場所 | 書く人 | 中身 |
|---|---|---|
| `personalEvents/{id}.sends[]` | 本人は**末尾に1件足すだけ**（`id, at, friendIds, from, note, status:'wait'`）。それ以外はサーバー | 予約の入力と、画面に出す結果の写し（`status, lineResult, pushResult, lineError, pushError, error, sentAt`） |
| `personalEvents/{id}.sendCancels[]` | 本人は**申し出を1件足すだけ** | 取り消したい予約の `id` |
| `personalEvents/{id}.nextSendAt` | 予約を足すときだけ「早いほう」に。それ以外はサーバー | 次に見に行く時刻 |
| `sendLedger/{hash}` | サーバーだけ（利用者は読めない） | 確保した月・人数・相手、LINEの状態、アプリ通知の状態、試行回数、ロック |
| `lineUsage/{月}_{uid}` | サーバーだけ | 1人あたりの今月の通数（月30通） |
| `lineQuota/hold_{月}` | サーバーだけ | `count`＝確保したがまだ確定していない数（アプリ内の予約枠）、`sent`＝アプリが送信確定した数 |
| `lineQuota/current` | サーバーだけ | 画面用の「全体の残り」（LINEの実使用量から予約枠を引いた数） |

## 状態の流れ（LINE）

`todo` →（送る直前に確保）`held` →（受け付けられた）`sent`
- 送れなかったとはっきり分かる（4xx・月の上限・429のまま5回）→ `returned`（個人の数と予約枠を戻す）
- 送れたか分からない（5xx・通信断・途中で止まった、のまま5回／取り消し／期限切れ）→ `unknown`（個人の数は戻さない。予約枠は外し、全体の残りでは「使った」側に数える）
- 確保の前に止まった（全体の枠・1人30通・相手なし・取り消し・期限切れ）→ `blocked`（何も数えない）

アプリ通知（`push:self`）はLINEと別に実行し、成功（`ok`）は二度と送らない。失敗は3回まで。途中で止まったものは `unknown` として重ねて送らない。
「送信済み」はLINE・通知サービスが受け付けたという意味で、端末に届いたかは確認できない（画面にも「届いた」とは出さない）。

## 同時実行・再実行

- 確保・確定・返却は、台帳・個人の数・予約枠を同じトランザクションで変える。台帳の状態が変わるのは1回だけなので、二重計上・二重返却にならない。数は0未満にならない。
- 全体の上限：`LINEの残り − （LINEに聞いた後にアプリが確定した数）− 予約枠 ≥ 人数` のときだけ確保する。
- 予約を取り消したあと・予定を消したあとに残った `held` は、5分ごとの見回り（`sweepHeld`）が閉じる。

## 以前の予約との互換

- 以前の行にある `reserved`・`leaseUntil`・`attempts` は信用しない（読み捨て、サーバーが書くときに消す）。一時エラーで再試行中だった行は、数え直しになる場合がある（多めに数える側＝上限は超えない）。
- 以前の版で `pushResult:'ok'` になっていた行は、アプリ通知を重ねて鳴らさない。
- 以前の版の画面（キャッシュ）で行を消して取り消そうとすると、新しいルールで拒否される（「取り消せませんでした」）。ページを開き直せば新しい取り消しになる。
