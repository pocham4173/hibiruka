# 写真カレンダーの訂正と読み直しの設計

設計反映日：2026年10月15日
状態：設計のみ。以下の新しい入口・復元機能は未実装、未公開。

## 目的と範囲

写真の読み取りが間違っていたとき、利用者本人がアプリの中で修正・読み直し・取り消しを完結できるようにする。開発者へのスクリーンショット送付や、友達の画面を別の人が確認することを通常の手順にしない。

今回の優先事項は次の3点に限定する。

1. 数日だけの間違いを日付ごとに直せる。
2. 全体のずれを写真の読み直しで訂正し、保存前に変更内容を確認できる。
3. 直前の写真取り込みを、後から追加した情報を壊さずに取り消せる。

これは誤読時の回復手順の設計であり、画像認識の精度改善・全書式対応とは別の完成条件を持つ。印刷物でも誤読は起こり得るため、「全社対応」「自動判定だから正確」とは表示しない。

## 現在できることと追加すること

| 項目 | 現在 | この設計で追加すること |
|---|---|---|
| 日付ごとの訂正 | ビジネスカレンダーの「会社の休日」から変更可能 | 間違いに気づいた場所から訂正先へ案内 |
| 写真の読み直し | 写真の再選択、原本比較、確認月の置換がある | 再登録のために設定を消さなくてよいことと、操作の順序を明示 |
| 保存前の比較 | 月ごとの変更日数・消える印を表示 | 日付ごとの変更前・変更後を一覧で比較 |
| 復元 | 写真取り込みを戻す履歴はない | 直前の写真取り込み1件の復元と競合検査 |
| 読み取り失敗 | エラー文を表示 | 撮り直し、日付訂正への具体的な入口を同じ画面に表示 |

以下のボタン名は実装する画面の仕様であり、現行画面に存在するという案内には使わない。

## 入口と3つの選択肢

カレンダーの近くと「仕事・休みの設定」に「読み取り結果を直す」を設ける。通常のカレンダーでは小さな案内リンクにとどめ、仕事用の入力欄を常時表示しない。日付が選択されていれば、その日付を引き継ぐ。

| ボタン | 補助文 | 遷移先 |
|---|---|---|
| 日付を選んで直す | 数日だけ違う・休みが抜けているとき | 月カレンダーで日付選択 → 会社の休日の訂正 |
| 写真から読み直す | 全体がずれている・多くの日が違うとき | 写真・PDF選択 → 読み取り → 月ごとの比較 |
| 取り込み前に戻す | 直前に保存した写真の取り込みを取り消す | 対象月・保存日時・戻る内容の確認 |

復元履歴がないときも理由を表示する。「戻せる写真取り込みはありません」。この機能の公開前に保存された取り込みには復元履歴がないことを明示し、日付訂正か写真の読み直しへ案内する。

## 日付ごとに直す

1. 月カレンダーで直したい日を押す。
2. 年月日を大きく表示し、「会社の休日」の種類を選ぶ。現在の会社設定で使っている名称・色を表示し、A/Bだけの固定一覧にしない。
3. 「この日を保存」で確定する。保存完了を確認するまで成功表示を出さない。

「会社の印を消す」と「出勤」は別の選択肢にする。未登録の日にも印を追加できる。保存失敗時は入力を残し、同じ画面で再試行できる。

自分だけの有給・午前休・午後休は既存の「自分の休み」に案内し、会社全体の印と混同させない。写真で未対応の会社独自区分や時間帯を、別の種類や終日の休みに黙って変換しない。対応できない区分はその理由を示し、保存対象にしない。

## 写真から読み直す

1. 「写真から読み直す」で端末内の写真・PDFを選ぶ。原本はアプリに永続保存していないため、画面を閉じた後は再選択が必要だと短く案内する。
2. 年と読み取る画像を確認して「休日を読み取る」を押す。PDFはページごとに扱う。
3. 元の写真と読み取り結果を月単位で比較する。拡大でき、前の月・次の月へ移動できる。未読の月を取り込んだように見せない。
4. 間違った日付の印を修正する。変更した月の「確認済み」は解除する。画像・年・PDFページが変わったら前の読み取り結果と確認状態を無効にする。
5. 保存する月にチェックし、「確認した○か月を保存」を押す。対象月と変更内容を最終確認してから入れ替える。
6. 保存成功後に対象月へ戻り、「○か月の会社の休日を更新しました」と「取り込み前に戻す」を表示する。

読み取り中、失敗時、中止時は登録済みの休日を変更しない。設定の初期化・アプリの削除・記録の削除を読み直しの条件にしない。保存済みの休日が自動で訂正されるとは説明しない。

### 保存前の比較

- 対象月、追加・変更・削除の日数を表示する。
- 日付ごとの「現在 → 保存後」を表示する。変更が多い場合は月単位で開閉できる。
- 印のない日も含めて対象月を置き換えること、古い誤読の印は消えることを明示する。
- 一つでも「要確認」が残る月は保存できない。月の全日付がそろわない結果も保存できない。
- 休日の印が0日の月は、見落としの可能性を知らせ、「この月には会社の休日の印がない」と原本を確認する追加チェックを必要とする。自動では全削除しない。この確認も認識精度を保証するものではない。
- 未選択月、予定、思い出、通知、自分の有給・半休を変更しない。
- 「戻せるのは、直前の写真取り込み1回です」と示す。新たな取り込みが成功するまでは、以前の復元履歴を残す。

## 取り込み前に戻す

直前に成功した写真取り込み1件について、保存日時・対象月・戻る印を表示する。「元の休日に戻す」でその取り込み対象の月をまとめて復元する。元画像の再添付は不要。別端末でも同じ本人アカウントなら利用できる。

- 戻すのは会社の休日の印だけ。設定全体を古い状態へ戻さない。
- 写真取り込み後に対象月の会社休日が変更されていたら、復元を実行しない。「取り込み後に変更した休日があります。その変更を守るため、一括では戻せません」と表示し、日付ごとの訂正へ案内する。強制上書きは設けない。
- 対象月以外の変更や、自分の有給・半休・予定の追加はそのまま保ち、復元を妨げない。
- 休日区分の名称などが取り込み後に変わり、同じコードでも意味が変わっている場合は、原本確認なしに古い印を復元しない。
- 取り消しは1回で完了する。二重押しや再送で繰り返し変更しない。取り消した取り込みの再適用は今回の範囲に含めない。
- 履歴は次の写真取り込みが成功するまで保持する。履歴を無制限に増やさず、アカウント削除時に削除する。

## 失敗時の画面

| 状況 | 表示 | 次の操作 |
|---|---|---|
| 年月・日付・凡例を読めない | 読み取り内容を確認できませんでした。登録済みの休日は変えていません。 | 別の写真を選ぶ／日付を選んで直す |
| 画像が小さい・切れている | 年・月・日付と、色や記号の説明が見える写真を選んでください。 | 別の写真を選ぶ |
| 読み取り回数の上限 | 今日の読み取り回数を使い切りました。日付ごとの訂正はできます。 | 日付を選んで直す |
| 保存前に別の変更があった | 確認中に休日が変更されました。最新の内容で確認し直してください。 | 最新の内容を確認 |
| 保存が確実に失敗した | 保存できませんでした。確認内容を残しています。 | 保存を再試行／閉じる |
| 保存の応答が届かず成否が不明 | 保存結果を確認しています。 | 保存履歴の照合後に、成功表示または再試行へ |
| 復元対象に後から変更があった | 取り込み後の変更を守るため、一括では戻せません。 | 日付を選んで直す |

通信が途切れただけで「保存していません」と断定しない。保存結果を確認するまで新しい取り込みを重ねず、同じ保存操作を識別して照合する。

## 実装時の保存方針

現行の会社休日は `personalConfig/{uid}.calendar.days`。現在の `saveCalendarConfig` と共通の月置換検査を拡張し、本人だけの保存先を維持する。旧共有モードでも共有の予定や他人の設定には書かない。

復元用に `personalCalendarRecovery/{uid}` を1件設ける設計とする。保持するのは、形式のバージョン、取り込みID、保存日時、対象月、対象月の変更前・変更後の印、使用した区分の意味を比較する情報、取り消し済み状態のみ。画像・PDF・友達の情報・認証情報は保存しない。対象は最大24か月、各日の値と件数に上限を設ける。

- 写真取り込みの保存と復元情報の更新を同じトランザクションで行う。片方だけ成功させない。復元情報が保存できなければ休日も更新しない。
- 保存前の比較は、確認画面を開いた時点とトランザクションで読んだ最新データの対象月を照合する。
- 復元時も、取り込みIDと対象月の現在値を取り込み直後の値と照合する。最新の予定やビジネス設定を読み直し、会社休日の対象月だけ復元する。
- 同じ保存操作の再試行には同じ取り込みIDを使う。成功済みなら再適用せず成功を返す。対象月に実質的な変更がない場合は復元履歴を置き換えない。
- 日付ごとの訂正・復元と、写真取り込みの履歴作成を区別する。手直しで新たな「写真取り込み履歴」を作らない。
- 新しい保存先はUID本人以外の読み書きを拒否し、型・許可キー・対象年月・日付値・件数・状態遷移を検査する。カレンダーとの整合性を `getAfter` 等で確認できるルールとし、保存・復元の原子性をエミュレーターで検査する。
- 古い画面から休日が変更された場合も、復元時の内容照合で上書きを防ぐ。新しい履歴フィールドを既存カレンダーへ埋め込んで、旧画面が消してしまう方式は採らない。
- アカウント変更時に下書きと表示中の履歴を破棄する。アカウント削除処理と本人による保存データ削除の対象に新しい復元情報を追加する。
- 画像認識APIの呼び出しは読み直し時のみ。日付訂正、比較表示、復元ではAIを呼び出さない。

## 完成条件

- 初めて使う人が、開発者や友達への確認依頼なしに3つの訂正方法へたどり着ける。
- 日付の追加・種類変更・削除、全体の読み直し、月を選んだ保存が行える。
- 読み取り失敗・中止・保存失敗で元の登録内容が変わらない。成否不明時は履歴照合で判断できる。
- 追加・変更・削除が保存前に比較でき、0件の月は追加確認なしに既存の印を消さない。
- 保存した直前の取り込みを画面を閉じた後も戻せる。対象外の月・予定・思い出・有給・半休を保持する。
- 競合、区分の意味の変更、二重押し、保存再試行、別端末、アカウント切替、旧画面からの変更で誤って上書きしない。
- 他人の復元情報の読み書きを拒否し、履歴の保存に失敗した場合は休日の更新も失敗する。アカウント削除で履歴も消える。
- この機能以前の取り込みには戻せない理由と代わりの修正方法を表示する。
- iPhoneとAndroidの実操作で、入口から訂正・読み直し・復元まで確認してから「使える」と案内する。模擬検査と実機確認は別々に記録する。

写真の誤認識そのものが解消したかどうかは、実写真による別の検証で判断する。この回復手順だけをもって「誤読しなくなった」とはしない。
