# LINEから記録する（受け取り係・Webhook）

## できること
- アプリの「設定」→「LINEから記録する」で一度つなぐと、ヒビルカのLINEに**位置情報**を送るだけで、その場所が今日の「思い出」に記録される。
- 記録後の返事に分類ボタン（クイックリプライ）を出し、押すと分類が変わる。
- 「今日」→ 今日の予定・記録、「また行きたい」→ ♥の付いた記録、「使い方」→ 説明を返す。
- 写真は今回は受け付けのみ（案内を返す）。お店の名前から探す機能は、ホットペッパーのAPIキーを取得してから追加する。

## 本人確認
- LINEからのリクエストは `x-line-signature`（チャネルシークレットのHMAC）を確認してから処理する。確認前にFirestoreへ触れない。
- アプリが自己申告したLINEユーザーID（招待承認・自分の登録）は、受け取り係の本人確認に使わない。
- アプリ（Firebaseでログイン済みの本人）が `lineLinkCodes/{10文字}` を作成する。ルールで持ち主・有効期限（11分未満）・個人用プロフィール／従来の持ち主を確認する。
- その番号をLINEから送ると、受け取り係が番号を消費（使い捨て）し、`lineAccounts/{LINEユーザーID}`（サーバー専用）と `lineLinks/{FirebaseUID}`（本人のみ読取・削除可）を作る。
- 受け取るたびに両方が一致することを確認する。アプリで「つなぐのをやめる」と `lineLinks` が消え、以後そのLINEからは書き込まれない。
- 番号は32文字×10桁（約10^15通り）で、10分で失効する。

## 送信数
- 返事は reply API のみ。LINE公式アカウントの月間送信数には数えない。
- つながっていない人の普通の文字には返事をしない（管理画面のチャットで手動対応できるように）。「お問い合わせ」には案内を返す。

## 公開
1. GitHubのSecretsに `LINE_CHANNEL_SECRET`（LINE Developers → Messaging APIチャネル → チャネル基本設定 → チャネルシークレット）を追加する。
2. マージ後、`LINE連携番号のルール反映` がルールをエミュレーターで検査してから公開する。
3. `ヒビルカ送信の修正反映` が Worker を配置する（`workers_dev: true` で公開URLができる）。定期送信は従来どおり確認モード→再開の手順で戻る。
4. 同じワークフローの最後で `line-worker/set-webhook.cjs` が Webhook URL（`https://hibiruka-line.<サブドメイン>.workers.dev/line/webhook`）をLINEに自動設定し、LINEの検証を実行してログに結果を出す（失敗しても送信には影響しない）。
5. LINE Official Account Manager → 応答設定で「Webhook」をオン、「応答メッセージ」をオフ（自動返信の二重防止）。この2つはAPIで変えられないため手動。

シークレットが無い状態で配置した場合、受け取り係は503を返すだけで、定期送信には影響しない。

## 検証
- tests/webhook.test.mjs：署名、番号の使い捨て・期限・持ち主確認、解除後の拒否、位置情報の記録と再送の重複防止、他人の記録を分類変更できないこと、今日・また行きたいの持ち主限定、従来の持ち主、返事がreply APIのみであること。
- security/personal.test.cjs：番号は本人だけ作成・読取・削除、期限・形式・プロフィール必須、`lineAccounts` は利用者から読めない、`lineLinks` は本人のみ。
- 実機（LINEアプリから位置情報を送る）での確認は公開後に行う。
