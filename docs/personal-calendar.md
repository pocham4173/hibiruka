# 自分のカレンダー

## 使い方

初回の月カレンダー、または設定の「自分のカレンダー」から開きます。「あとで」でスキップできます。A班・B班・班なし、六曜の表示を選択できます。基本カレンダーには日曜・祝日（赤）、土曜（青）、祝日名、六曜を表示します。会社の休日と国民の祝日は独立しています。

写真・PDFから登録する場合は、年と凡例を含む画像を選択し、カレンダーの最初の西暦年を確認して「休日を読み取る」を押します。PDFは端末内で1ページを画像に変換します。複数ページは1ページずつ確認・保存し、次のページはファイルをもう一度選択して追加します。読み取り結果は日付と種類を編集でき、対象外の行を外せます。不明な種類は「要確認」のまま保存できません。原本との比較確認にチェックしてから保存します。抜けた日や変更は「手入力」、または月カレンダーの日付→「この日の休日を変更」で修正します。

取り込みは日付単位の追加・置換です。画像にない既存の休日、予定、思い出、通知は変更しません。翌年分を追加可能。1アカウント合計1,200日まで。出勤日の印や、印の削除にも対応しています。旧共有モードも本人の休日設定を別途読み込みます。

## 保存・読み取り

- `personalConfig/{uid}.calendar` に `{version:1,configured,team,showRokuyo,days}` を保存。既存のUID本人ルールを維持し、型・許可キー・件数を検査。更新はtransactionで最新のdaysに操作分だけ合成し、calendarフィールド全体を置き換える（削除した印がmergeで残ることを防ぐ）。元のプロフィールは維持。アカウント削除時は既存処理でこのドキュメントごと削除されます。
- `POST /ai/calendar` は既存のFirebase IDトークンの署名・プロジェクト・有効期限、Originを検証。本文はストリーム読み取りで2.8MBまで。JPEGのdata URLのみ受け付け、外部画像URLを取得しません。
- 既存のGemma 4 Workers AIモデルの画像入力を使用。画像に含まれる指示には従わせず、赤い日付・曜日から休日を推測させません。返答のJSON、日付、年、種類をサーバー側で検査。重複して矛盾した日は要確認。空結果・不正・切れたJSONは失敗として返します。モデルエラー時の自動再試行・テキストモデルによる代替はありません。
- `calendarUsage` は1人1日4回・全体40回（JST、transaction）。さらに既存`aiUsage`上限に計上。生画像や読み取り結果をサーバーのDB・ログへ保存しません。成功の返答は確認用で、本人の保存操作があるまで休日設定は更新しません。
- AIの実画像認識精度は模擬テストでは保証できません。鮮明な画像でも確認を必須とし、読めない場合は手入力を利用します。

## ビジネスモード（2026-10）

カレンダー上の「ふだん／ビジネス」で切り替える。休日設定の入口はビジネスに統一し、選択日を引き継ぐ。「仕事の設定」から会社写真・既存の手入力も利用できる。

- 日付→自分の休み：休み／有給／出勤、終日／午前／午後、自由な名前。会社の `days` を残して `calendar.business.personal[date]` に差分を保存。「変更を戻す」は差分だけ削除する。普段のカレンダーにも紫の文字付きバッジを表示する。
- 日付→会社の休日：会社の原本の印を編集。A/Bに加えて追加の班8種類、全休等の名前・色・表示を変更できる。表示は全班、集計は自分の班＋全休・休み。祝日を会社休日に自動変換しない。
- 年度開始月日・有給集計開始月日は別に設定。画面の月を含む1年間を集計。確認済み範囲が年度全体を覆う場合のみ年間休日と表示し、それ以外は登録済み・未確定と表示。検証済み会社カレンダーの再取り込みのみ明示範囲を引き継ぐ。旧データから確定範囲は推測しない。
- 有給は登録分を日付で取得済み／これからに分け、半日を0.5日として表示する。承認状態・残高・付与日数・給与計算は扱わない。
- 仕事の予定・締切・勤務・メモは `business.entries`。自由入力と候補、任意の時刻・メモ、毎週／毎月最大24回の登録。月末は翌月末へ丸める。編集・削除・完了は1件単位。期限超過の未完了も月一覧に表示。仕事の予定は通常の思い出・共有・LINE送信に入らない。勤務の登録だけでは休日の差分を変えない。
- 次の休み・連休は今日から365日以内の登録済み終日休みのみ。出勤差分を優先し、半休を終日休みに数えない。

保存先は既存と同じ本人専用 `personalConfig/{uid}.calendar`。一度のトランザクションで最新値へ必要なキーだけを反映する。名前、記録、通知、他の日付を保持する。写真取り込みもビジネス差分を保持する。仕事予定500件・個人差分1200日が上限。新しいrulesは旧形式を許容し、新形式保存後に古いクライアントがbusinessフィールドを消す更新を拒否する。`business-calendar-rules.yml` は本番の既存ルールを保持してエミュレーター検査後に反映し、使い捨てアカウントで保存・復元・分離・旧画面保護を確認して削除する。
