# 自分のカレンダー

## 使い方

初回の月カレンダー、または設定の「自分のカレンダー」から開きます。「あとで」でスキップできます。A班・B班・班なし、六曜の表示を選択できます。基本カレンダーには日曜・祝日（赤）、土曜（青）、祝日名、六曜を表示します。会社の休日と国民の祝日は独立しています。

写真・PDFから登録する場合は、年と凡例を含む画像を選択し、カレンダーの最初の西暦年を確認して「休日を読み取る」を押します。PDFは端末内で1ページを画像に変換します。複数ページは1ページずつ確認・保存し、次のページはファイルをもう一度選択して追加します。読み取り結果は日付と種類を編集でき、対象外の行を外せます。不明な種類は「要確認」のまま保存できません。原本との比較確認にチェックしてから保存します。抜けた日や変更は「手入力」、または月カレンダーの日付→「この日の休日を変更」で修正します。

取り込みは日付単位の追加・置換です。画像にない既存の休日、予定、思い出、通知は変更しません。翌年分を追加可能。1アカウント合計1,200日まで。出勤日の印や、印の削除にも対応しています。旧共有モードには個人設定を混在させず、基本カレンダーのみ表示します。

## 保存・読み取り

- `personalConfig/{uid}.calendar` に `{version:1,configured,team,showRokuyo,days}` を保存。既存のUID本人ルールを維持し、型・許可キー・件数を検査。更新はtransactionで最新のdaysに操作分だけ合成し、calendarフィールド全体を置き換える（削除した印がmergeで残ることを防ぐ）。元のプロフィールは維持。アカウント削除時は既存処理でこのドキュメントごと削除されます。
- `POST /ai/calendar` は既存のFirebase IDトークンの署名・プロジェクト・有効期限、Originを検証。本文はストリーム読み取りで2.8MBまで。JPEGのdata URLのみ受け付け、外部画像URLを取得しません。
- 既存のGemma 4 Workers AIモデルの画像入力を使用。画像に含まれる指示には従わせず、赤い日付・曜日から休日を推測させません。返答のJSON、日付、年、種類をサーバー側で検査。重複して矛盾した日は要確認。空結果・不正・切れたJSONは失敗として返します。モデルエラー時の自動再試行・テキストモデルによる代替はありません。
- `calendarUsage` は1人1日4回・全体40回（JST、transaction）。さらに既存`aiUsage`上限に計上。生画像や読み取り結果をサーバーのDB・ログへ保存しません。成功の返答は確認用で、本人の保存操作があるまで休日設定は更新しません。
- AIの実画像認識精度は模擬テストでは保証できません。鮮明な画像でも確認を必須とし、読めない場合は手入力を利用します。

## 暦データ・依存関係

- 国民の祝日：内閣府 https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html / `syukujitsu.csv`（1955–2027、2026-10-12取得）。CSVの「休日」表記を維持。振替休日と祝日に挟まれた休日を含みます。2028年以降は未収録と表示し、予測の祝日を表示しません。
- 六曜：日本の旧暦計算から生成した2020–2032年の静的データ。タイムゾーンをAsia/Tokyoに固定して生成し、閲覧端末のタイムゾーンや中国暦Intlに依存しません。2033年以降は未収録として表示。六曜は参考表示です。
- 計算ソース：kawasawa/koyomi `a400e9399a3e04df09e18e6cdf1de54449c5e7df` の `JapaneseLunisolarCalendar.ts`。MITライセンスを `scripts/vendor/koyomi-LICENSE.md` に同梱、元の高野・長野両氏のクレジットを維持。
- 再生成：内閣府CSVを保存し、Node 24以上で `TZ=Asia/Tokyo node scripts/build-calendar-data.mjs /path/to/syukujitsu.csv`。生成結果の収録年・祝日・閏月境界を検査してから更新。
- PDF.js 6.4.299（Apache-2.0）をjsDelivrからPDF選択時のみロード。ソース・ライセンス： https://github.com/mozilla/pdf.js 。PDF本体をCDNには送りません。画像をAIへ送る前に画面で用途を説明します。
- 画像入力仕様： https://developers.cloudflare.com/workers-ai/models/gemma-4-26b-a4b-it/

## 公開手順

1. `security/personal.rules` の新しい許可フィールドを本番ルールへ既存の運用手順で反映。
2. `line-worker/calendar.mjs` とルートをWorkerへデプロイ（AIバインディング・既存認証を利用、送信処理の設定を変更しない）。
3. フロントのHTMLと3つのcalendar JS、規約を公開。
4. 実アカウントで添付→読み取り→確認→保存→再読み込み、別端末、A/B切替を確認。本物のLINE送信は本機能の検査には不要。

公開前は模擬AI応答とFirestoreエミュレーターで検査。本番データの書き込みや有料プラン変更は実施しません。

## 検査結果（2026-10-12）

- 既存機能を含むNodeテスト200件合格。その後、画面の保存・削除と画像取り込みの確認必須を検査する2件を追加し合格。
- Firestoreエミュレーター16件合格（他人の設定アクセス拒否、カレンダースキーマ、AI回数情報へのアクセス拒否を含む）。
- Workerのdry-runビルド成功。
- Chromiumの390px・320px幅で月表示のはみ出しなし。実PDFをPDF.jsで表示し、模擬AI応答の確認・保存・翌年の追加を操作確認。画像ファイルの取り込みは画面テストで模擬検査。
- 実Cloudflare AIでの写真認識、本人の実アカウント・iPhone・別端末での再読込は未実施。本番への公開前に確認が必要。
